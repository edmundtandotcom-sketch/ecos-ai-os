# /build-interactive — Interactive & Gamified Platform Build Standards

Read `00_AI_OPERATING_SYSTEM\00_COMMAND_CENTER\13_INTERACTIVE_BUILD_STANDARDS.md` in full before doing anything else. It is short — read it every time, do not rely on memory of a prior session.

Then, before writing any code or delegating a build:

1. **State the sales-instrument framing explicitly** for this specific build: who is this for, what do they want to feel by the end, and what does the result need to prove to make the next action (booking, buying, signing up) feel obvious rather than bolted on.
2. **Confirm the result-reveal plan**: a "thinking/calculating" beat before the result, and a result screen that shows proof of real personalized work — not just states a category.
3. **Name one real comparable** to benchmark interactivity against (a competitor's live tool, a prior build, or an acknowledged best-in-class reference) — actually visit/drive it if it's live, don't guess from memory.
4. **Confirm the compliance boundary** — which locked prohibited-claims list or positioning master governs this build's copy, so "sharper" never drifts into an unproven claim.

Delegate the build per the standing Orchestration Mandate (Sonnet for execution, Opus for high-stakes copy/architecture — never spawn another Fable/lead-model agent).

**Before presenting or publishing anything visual/interactive, run the mandatory QA discipline from §7 of the standards file — real screenshots in a properly-foregrounded browser, edge-case states via any QA shortcut the build includes, geometry checks to investigate (not replace) what a screenshot shows, a compliance text-scan.** A subagent's self-report or a passing DOM check is not sufficient on its own — this has caused real, missed, user-visible bugs before. If a subagent says it couldn't get screenshots working, treat that as a flag to re-verify personally, not as QA already done.

If this build teaches a new lesson not already in the standards file, add it there before closing the session — that file exists specifically so lessons don't have to be re-learned.
