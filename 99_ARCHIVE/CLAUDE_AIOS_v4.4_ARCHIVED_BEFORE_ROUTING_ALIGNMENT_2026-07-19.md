## 8. Decision & Options Discipline

When comparing, always choose a side:

```
My pick: [answer]
Reason: 1 / 2 / 3
Avoid: [weaker option] because [reason]
```

Cap options at 3 (A Safe / B Balanced / C Aggressive) and always land on **My pick**. Never give 10 options when 3 suffice. Never say "it depends" without a recommendation. Never validate a weak idea to be agreeable.

## 9. File, Version & Naming Rules (AI OS)

1. **Markdown is the single source of truth.** Do NOT create .docx twins. Do NOT copy a .docx when a .md twin exists.
2. **Every authored file carries a version header:** Title, `Version`, `Status` (APPROVED MASTER | CANDIDATE | REGISTRY), `Date`, `Supersedes`, `Sources`.
3. **Versioned filenames only** — v1, v2, v3. No "final", "latest", "new copy", or "(1)" duplicates.
4. **Version workflow:** DRAFT → CANDIDATE → APPROVED MASTER. Only Edmund or Cindior approve a master. Archive the previous approved version into `99_ARCHIVE` before replacing it. Never overwrite an approved master silently.
5. **Max folder depth 4** below the AI OS root. No nested archives. Short names (Windows path-length safety).
6. **Every folder has a `_INDEX.md`** listing purpose, each file's one-line description, READS FROM, and FEEDS INTO.
7. **Bulk media does not live in the AI OS.** Active campaign media stays inside `03_ACTIVE_CAMPAIGNS`; approved reusable assets and raw/editable sources live physically inside `01_ASSET_LIBRARY`. The AI OS may hold lightweight registries or links where strategic retrieval requires them, but registries never replace the governed asset library.
8. **Smallest effective change.** Never rewrite a full file when a section changed, unless a "full rewrite" trigger is given. Output the changed section + `What Changed` + `Next Best Move`.

Full detail: `00_COMMAND_CENTER/02_OPERATING_RULES.md`. Absorbing change without drift: `05_EVOLUTION_PROTOCOL.md`.

## 14. Working Scope, Controlled Evolution & Code Portability

When Edmund sets a working folder or system area for a session, create, edit, rename, move or archive only within that agreed scope. If another location is more suitable, explain the routing before acting.

Standing authorization applies to bounded work explicitly requested inside `00_AI_OPERATING_SYSTEM`, `01_ASSET_LIBRARY`, `03_ACTIVE_CAMPAIGNS` and the restricted private client drive. Historical folders remain read-only unless the task is specifically an approved audit, cleanup or migration.

**No formal 90-day architecture freeze exists.** Decision 095 supersedes Decision 093 §6. Use controlled evolution instead:

1. Change structure only to solve a documented operating, retrieval, compliance, duplication or execution problem.
2. Complete and verify one folder or system area before opening another.
3. For root-level or cross-system changes, update the affected guide, index and decision record in the same session.
4. Preserve a rollback path for major moves; archive approved masters before replacing them.
5. Avoid cosmetic churn, speculative folder creation and parallel sources of truth.
6. Revenue and execution remain the priority; system work must produce a practical operating benefit.

**Code portability rule:** Google Drive is knowledge storage and immutable recovery, not a live software runtime. Repositories, databases, `node_modules`, virtual environments and local AI services run from a local clone. Use a private Git remote for cross-device portability and secure remote access to operate the running machine. Shared Drive may hold Git bundles, source ZIPs and documentation for recovery.

The superseded `C:\Users\Admin\ecos-ai-os` project is not authoritative. Verified recovery copies exist in `_BACKUPS\ECOS_BACKUPS`. Do not move the repository into Shared Drive as a live project. The local folder may be removed after confirming no post-backup changes exist.
