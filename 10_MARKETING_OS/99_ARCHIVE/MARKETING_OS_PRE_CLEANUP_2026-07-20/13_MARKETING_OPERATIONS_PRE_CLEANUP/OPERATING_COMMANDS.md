13 standing commands. Say the command name to invoke; the desk executing is the Marketing & Ads Desk unless noted.

## 1. START CAMPAIGN
Input: offer, audience, engine. Process: run CAMPAIGN_BRIEF.md, assign CMP- ID, file in 08_CAMPAIGNS/PLANNED. Output: filed brief, pending Edmund/Cindior approval.

## 2. BUILD CAMPAIGN PACK
Input: approved CAMPAIGN_BRIEF.md. Process: run CREATIVE_BRIEF.md + FUNNEL_BRIEF.md for every asset/funnel needed, assign CR-/CP-/FUN- IDs. Output: complete asset set, Stage 5–7 done.

## 3. AUDIT CAMPAIGN
Input: CMP- ID. Process: check Stage 8–9 gates, registry completeness, evidence-tier labelling. Output: pass/fail list with fixes.

## 4. AUDIT ASSET
Input: CR-/CP- ID. Process: re-run the 18-criteria QA scorecard. Output: updated score, revise/launch/kill call.

## 5. REVIEW PERFORMANCE
Input: campaign or channel, period. Process: run PERFORMANCE_REVIEW.md against diagnosis hierarchy. Output: kill/keep/iterate/scale call.

## 6. WEEKLY MARKETING REVIEW
Input: none (runs on cadence). Process: run WEEKLY_MARKETING_REVIEW.md across all ACTIVE campaigns/experiments. Output: weekly roll-up, logged to AI OS Session Log.

## 7. MARKET INTELLIGENCE SCAN
Input: none or a named competitor/trend. Process: pull from 03_MARKET_INTELLIGENCE sources + live automations. Output: flagged signal, Tier-4-labelled, routed to relevant campaign/experiment.

## 8. FIND BEST FRAMEWORK
Input: awareness stage, objective. Process: query 05_FRAMEWORK_LIBRARY/FRAMEWORK_REGISTRY.csv by stage/objective/evidence tier. Output: ranked framework shortlist with "when NOT to use" flags.

## 9. FIND BEST CREATIVE FORMAT
Input: channel, objective. Process: query 07_CREATIVE_LIBRARY + 06_CHANNEL_PLAYBOOKS for format fit and evidence tier. Output: recommended format(s), cited.

## 10. CAMPAIGN POSTMORTEM
Input: CMP- ID at COMPLETED. Process: run CAMPAIGN_POSTMORTEM.md, extract learnings. Output: closed record, LEARNING_REGISTRY.csv rows added.

## 11. SHOW SOURCE OF TRUTH
Input: a topic/claim. Process: query 00_COMMAND_CENTER/SOURCE_OF_TRUTH_MAP.md and the brief's §4 map. Output: authoritative file path + status.

## 12. CHECK CONFLICTS
Input: a topic/asset. Process: query 00_COMMAND_CENTER/CONTRADICTION_REGISTER.md for matching C0# items. Output: list of open contradictions touching the topic, with the OPEN/pending-Edmund flag.

## 13. UPDATE MARKETING OS
Input: a proposed rule/framework/registry change. Process: run CHANGE_PROPOSAL.md, file to 14_CHANGE_LOG/PENDING_CHANGES, add CHANGE_LOG.csv row. Output: pending change record, routed for approval per CHANGE_CONTROL.md.
